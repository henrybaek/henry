# 증바람 도감 정기 갱신 절차

사이트: https://henrybaek.github.io/henry/  (저장소 henrybaek/henry, main 브랜치 루트의 index.html)
보고 언어: 모든 보고·메시지는 한국어. 간결한 보고서체.

## 0. 이번 회차에 할 일이 있는지 판단
1. `build/meta.json`을 확인한다. `patch`=게임 패치(공식 노트 반영분), `stats`=통계 반영 패치. **갱신 판단은 `stats` 기준**이다.
2. https://arammayhem.com/ko-kr/tier-list/ 를 WebFetch로 열어 현재 통계 기준 패치를 확인한다.
3. 리그 오브 레전드 공식 패치 노트(https://www.leagueoflegends.com/ko-kr/news/tags/patch-notes/)에서 최신 패치 번호와 '무작위 총력전: 아수라장(증강 칼바람)' 관련 변경을 확인한다.
4. 통계 사이트 패치가 meta.json의 `stats`와 같고 공식 패치 노트에도 새 패치가 없으면: 파일을 바꾸지 않고 카톡도 보내지 않고 종료한다(갱신할 때만 보고).
5. 공식 패치는 나왔지만 통계 사이트가 아직 이전 패치면: `patch`가 이미 새 패치면 아무것도 하지 않고 종료. `patch`도 이전이면 공식 노트 기준 1차 반영(삭제·신규 증강, balance.json, changes.json)만 하고 `patch`만 올린 뒤 카톡 보고.
6. 통계 사이트가 새 패치로 넘어가면 전체 갱신 후 `stats`도 올린다. 신규 증강(aug_meta.txt 티어 `NEW`)은 이때 실제 등급·티어·선택률·추천 챔피언으로 바꾼다.

## 1. 공식 패치 노트에서 변경점 정리
- 아수라장(증강 칼바람) 항목: 신규·삭제·변경 증강, 아수라장 전용 챔피언 조정, 시스템 변경.
- 일반 챔피언·아이템 버프/너프 중 칼바람에 영향이 큰 것.
- 공식 문서에 없는 내용은 추측해서 쓰지 않는다.

## 2. 데이터 파일 갱신 (모두 `build/` 안, 구분자 `|`)
| 파일 | 형식 | 갱신 방법 |
|---|---|---|
| data.txt | id\|이름\|티어\|승률\|프리즘3\|골드3\|실버3\|핵심아이템3\|신발 | https://arammayhem.com/ko-kr/build/{id}/ 를 챔피언마다 WebFetch. 프롬프트 예: "한국어 표기 그대로 한 줄로만 출력: 챔피언\|티어\|승률\|프리즘 증강 3개(쉼표)\|골드 증강 3개\|실버 증강 3개\|핵심 아이템 순서(쉼표)\|신발". 한 번에 10개씩 병렬로. |
| aug_meta.txt | 이름\|등급\|티어\|선택률 | https://arammayhem.com/ko-kr/augments/ 전체 목록. 순서는 사이트 순서 그대로. |
| aug_raw.txt | 이름\|원문 요약\|많이 고르는 챔피언 6명 | 신규·변경된 증강만 https://arammayhem.com/ko-kr/augments/{slug}/ 에서 수집. 슬러그는 목록 페이지에서 확인. |
| aug_easy.txt | 이름\|쉬운 설명\|어울리는 챔피언 | 신규·변경 증강만 새로 작성. 기존 문체(1~2문장, 쉬운 말, 수치는 핵심만)를 따른다. |
| removed.txt | 이름\|등급\|삭제 패치\|한 줄 설명 | 라이브에서 삭제된 증강 추가. 여기 있는 증강은 챔피언 추천에서 자동 제외된다. |
| roles.txt | id\|역할 | 신규 챔피언만 추가. |
| meta.json | patch, stats, collected | 게임 패치, 통계 반영 패치, 갱신일(YYYY.MM.DD). |
| balance.json | {챔피언id: [상향/하향/조정, 한 줄 요약]} | 공식 패치 노트의 챔피언 조정. 패치마다 새로 작성(이전 패치 내용은 지움). 챔피언 카드에 표시됨. |
| changes.json | 배열 맨 앞에 새 항목 추가 | {"date","patch","title","items":[...]} items 문장 앞에 [상향]/[하향]/[신규]/[삭제]/[변경] 표시. 변경 많은 챔피언 티어 이동(예: "[상향] 케이틀린 A→S")과 공식 패치 핵심을 6~12줄로. |

- data.txt 증강 중 aug_meta.txt에 없는 이름이 나오면 그 증강이 삭제된 것인지 확인해 removed.txt에 넣는다.
- 삭제된 증강은 aug_meta/aug_raw/aug_easy에서 지우고 removed.txt에 `이름|등급|삭제 패치|이전 효과 한 줄`로 추가한다.

## 3. 생성·검증·게시
1. 저장소 루트에서 `python3 build/build.py` 실행. 종료 코드가 0이 아니거나 '사전에 없는 증강' 경고가 남으면 해결 후 다시 실행.
2. `node -e` 로 index.html의 <script> 문법 확인.
3. 이전 data.txt와 비교해 티어 변동 챔피언 목록을 뽑아 changes.json 내용과 맞는지 확인.
4. 커밋 메시지 "증바람 도감 {패치} 갱신" 으로 main에 push.
5. 1~2분 뒤 https://henrybaek.github.io/henry/ 를 WebFetch해 새 패치 번호가 보이는지 확인.

## 4. 카톡 보고 (mcp__PlayMCP__KakaotalkChat-MemoChat, 200자 이내)
형식:
```
[증바람 도감 {패치} 갱신]
상향: …(2~3개)
하향: …(2~3개)
증강: 신규 n·삭제 n·변경 n
상세: henrybaek.github.io/henry
```
- 200자를 넘으면 항목을 줄인다. 상세는 사이트 '업데이트 소식'에 있다.
- 카톡 도구가 없거나 실패하면, 같은 내용을 세션 마지막 보고로 남긴다.
- 실패(수집 불가, 사이트 구조 변경 등)로 갱신하지 못했을 때도 카톡으로 "[증바람 도감] 갱신 실패: 사유" 를 보낸다. 이때는 기존 사이트를 건드리지 않는다.

## 5. 앱(PWA) 관련 파일
- manifest.webmanifest, sw.js, icons/ 는 앱 설치·오프라인용. 데이터 갱신 때는 건드리지 않는다.
- sw.js는 페이지를 최신 우선으로 받으므로 index.html만 바꿔도 앱에 자동 반영된다.
